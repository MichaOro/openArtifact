## 8.1 Security Concepts

Decisions: [ADR-008](../../adr/008-security-operations.md) (foundation), [ADR-016](../../adr/016-access-protection-integration-api-and-mcp.md)
(access protection), [ADR-017](../../adr/017-request-hardening-and-signed-sessions.md) (hardening, sessions),
[ADR-023](../../adr/023-safety-model-of-execution-nodes.md) (execution nodes),
[ADR-024](../../adr/024-credential-store.md) (credentials). Reporting a vulnerability: [SECURITY.md](../../../../SECURITY.md).
Guides: [security](../../../guides/security.md), [credentials](../../../guides/credentials.md),
[execution nodes](../../../guides/execution-nodes.md).

**Threat model.** A self-hosted instance for one team. Attackers considered:

| Attacker | Capability | Answer |
|----------|-----------|--------|
| Anyone who can reach the port | Calls the API, opens the pages | The access token gates everything; without a token the pages are open **by design** (open mode) and then nothing sensitive may run |
| A foreign web page | CSRF through a signed-in browser, DNS rebinding | Cross-site guard, host check, `SameSite=Strict` cookie |
| A malformed or oversized request | Exhaust memory or confuse parsers | Body limit, validation, caps on runs and streams |
| A leak through logs, API responses, events or step results | Secrets in text | Masking in logs and results ([8.3](08.03-logging-observability.md), [6.8](../06-runtime-view/06.08-credential-resolution.md)) |
| Someone who controls an HTTP node's target or a response | SSRF to internal services; hostile text in a response | Address checks, no redirects, size limits ([8.5](08.05-execution-nodes-safety.md)); output is treated as data |
| A user who can edit pipelines | **Runs code**: a Code node is a shell or Python script with the rights of the application | Not prevented, only bounded: limits, token required, switch ([8.5](08.05-execution-nodes-safety.md)) |

Not considered: a malicious holder of the token (one shared token, no roles: whoever may edit pipelines is effectively an
operator of the host account) and a compromised host or container runtime.

**Layers, from the outside in.** (1) Network: published on `127.0.0.1` by default; TLS and rate limiting belong to a
reverse proxy. (2) Request hardening: headers, host, size, cross-site ([below](#request-hardening-middlewares-outermost-first)).
(3) Access gate: token or session. (4) Validation and the refusal rules of the services (`ArtifactError`, [8.2](08.02-error-handling.md)).
(5) Execution nodes: limits, address checks, masking, the open-mode refusal. (6) The container: non-root, read-only
file system, no capabilities, memory and process limits. No layer is a sandbox for Code nodes; the first four do not
apply to what a Code node does once it runs.

### Access protection

- One API token (`OPENARTIFACT_API_TOKEN`, at least 32 characters) protects the whole application: pages, the browser API,
  Swagger, `/api/v1` and `/mcp`. Open paths: `/health`, `/login`, `/logout`, `/static/`. Without a token (**open mode**) the pages and the
  browser API are open (the startup log warns), and `/api/v1` and `/mcp` answer `401`. In open mode **Code nodes are refused**
  (the node fails with "Code nodes need OPENARTIFACT_API_TOKEN") and credentials cannot be saved, because anyone who reaches
  the port could otherwise write and run code or read through a node; `OPENARTIFACT_CODE_NODES_WITHOUT_TOKEN=true` lifts
  the first refusal for local development on a trusted machine (a warning is logged at start).
- A request is accepted with `Authorization: Bearer <token>` (compared in constant time) or with a valid session cookie.
  The MCP server accepts only the bearer header.
- **Session cookie:** `<issued-at>.<HMAC-SHA256(secret_key, "session:<issued-at>:<token>")>`, never the token; the server
  refuses it after 30 days; `HttpOnly`, `SameSite=Strict`, `Path=/`; when secure also `Secure` and the name
  `__Host-oa_session`. Secure follows `OPENARTIFACT_COOKIE_SECURE` (`auto`: the request scheme is https). Changing the token
  or the secret key ends all sessions; there is no per-session revocation, and logout only clears the browser's cookie.
- The application **refuses to start** with a token shorter than 32 characters or with a token and a missing, default or
  shorter than 32 characters secret key. A wrong sign-in costs half a second; there is no rate limiting beyond that.

### Request hardening (middlewares, outermost first)

| Layer | Rule |
|-------|------|
| Security headers | CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'` (`'unsafe-inline'` for scripts only with `OPENARTIFACT_CSP_SCRIPT_UNSAFE_INLINE`); `X-Content-Type-Options: nosniff`; `Referrer-Policy: same-origin`; `X-Frame-Options: DENY`; `Strict-Transport-Security` over HTTPS. `/api/docs` has its own policy that allows `cdn.jsdelivr.net` |
| Host check | `OPENARTIFACT_ALLOWED_HOSTS` (supports `*.example.com`); other hosts get `400`; empty list: no check; `/health` exempt. Covers `/mcp` too |
| Body limit | 1 MiB (`OPENARTIFACT_MAX_REQUEST_BYTES`, `413`); 4096 bytes for `/login` |
| Cross-site guard | Unsafe methods get `403` when `Sec-Fetch-Site` is `cross-site` or `same-site`, or `Origin` differs from `Host`; requests without those headers (curl, scripts, MCP clients) pass; unsafe `/api` requests with a body must be `application/json` (`415`) |
| Caps | `OPENARTIFACT_MAX_CONCURRENT_RUNS` (`429`), `OPENARTIFACT_MAX_SSE_SUBSCRIBERS` (`503`) |

A reverse proxy must keep the `Host` header and send `X-Forwarded-Proto` (see the
[reverse proxy guide](../../../guides/reverse-proxy.md)).

### Secrets, credentials and logging

- **Settings secrets** (`OPENARTIFACT_API_TOKEN`, `OPENARTIFACT_SECRET_KEY`) are environment variables only: none in code or
  in the database. `deploy/.env` is git-ignored and excluded from the image by the `.dockerignore` allow-list. The secret
  key signs the session cookie and, through a derived key, encrypts the credentials.
- **Credentials** (named values that HTTP and Code nodes use) **are stored in the database, encrypted**: table `secrets`,
  AES-256-GCM, key derived with HKDF-SHA256 from the secret key (own `info` string `openartifact/secret-store/v1`, so the
  cookie key and the encryption key differ), a random 96-bit nonce per value, the credential's name as associated data
  (a ciphertext moved to another name does not decrypt), stored as a version byte `0x01`, the nonce and ciphertext with tag, at most 8 KiB.
  Names are `[A-Z][A-Z0-9_]{0,63}`. They can be saved only with a token **and** a secret key of the operator's own (`409`
  otherwise), through the API only: there is no UI yet. The API shows names and dates, never values. Details and limits:
  [8.6](08.06-credential-store.md).
- **Using a credential:** a node holds a name (`${secret:NAME}` in an HTTP node, a name list in a Code node, at most 32
  per node); the value is resolved when the node runs, and every form of it (raw, percent-encoded, Base64, JSON-escaped) is
  removed from the node's output, reason and data and from every log line while the node runs
  ([6.8](../06-runtime-view/06.08-credential-resolution.md)).
- **Honest limits:** whoever has the database *and* the secret key reads every credential; a changed key makes them
  unreadable (no rotation); a Code node that is given a credential can leak it on purpose in a transformed form that masking
  does not recognise; a Code node can read the database file (same user), where credentials are encrypted and
  the key is not reachable (see below).

### Container

- Multi-stage build; the runtime image has no build tools or development dependencies, and the build context is an
  allow-list (`.dockerignore`).
- Runs as UID 1000 on a **read-only root file system**; only `/data` (volume) and a tmpfs `/tmp` are writable; `/app` and the
  installed package are root-owned. All capabilities dropped, `no-new-privileges`, 256 processes, a memory limit (1 GiB).
  No privileged mode, no Docker-in-Docker. Definition: [`deploy/docker-compose.yml`](../../../../deploy/docker-compose.yml),
  explanation: [chapter 7](../07-deployment-view.md).
- Published on `127.0.0.1` by default; `OPENARTIFACT_BIND=0.0.0.0` opens it to the network and needs a token.
- CI audits the runtime dependencies weekly (`pip-audit`) and Dependabot proposes updates.

### Execution nodes (summary)

Full text in [8.5](08.05-execution-nodes-safety.md).

- **Code node:** child process (`sh` or `python -I`) in its own process group, with a fresh environment (no application
  setting, only the node's credentials), `RLIMIT_CPU`, `RLIMIT_AS`, `RLIMIT_NPROC`, `RLIMIT_FSIZE`, `RLIMIT_NOFILE`, no
  core files, a timeout of at most 600 s, output limits, `PR_SET_PDEATHSIG`, a registry that lets the next start kill
  orphans. The application makes itself non-dumpable (`PR_SET_DUMPABLE=0`) so the child cannot read its environment
  (token, key): hardened against reading the parent's environment, **no sandbox**.
- **Not covered:** no network namespace (a Code node reaches every address the application can, including metadata
  services and internal hosts), no file system isolation (it reads and writes what the application's user can, the database
  included), the same user as the application, no cgroup (limits are per process or per user).
- **HTTP node:** the host name is resolved by the application, every address is checked, and the request goes to the
  checked address (DNS-pinning); cloud metadata addresses are always refused, loopback and private networks unless
  `OPENARTIFACT_HTTP_ALLOW_PRIVATE_NETWORKS`; redirects are never followed; no proxy from the environment; response size
  and time are bounded.
- **Outputs are data.** Results of HTTP and Code nodes come from outside; the MCP tool descriptions tell an agent never to
  treat them as instructions, but a client may ignore that.
- **Switch:** `OPENARTIFACT_CODE_NODES_ENABLED=false` forbids Code nodes completely.
