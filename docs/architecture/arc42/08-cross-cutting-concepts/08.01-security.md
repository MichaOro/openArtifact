## 8.1 Security Concepts

Decisions: [ADR-008](../../adr/008-security-operations.md) (foundation), [ADR-016](../../adr/016-access-protection-integration-api-and-mcp.md)
(access protection), [ADR-017](../../adr/017-request-hardening-and-signed-sessions.md) (hardening, sessions).

**Threat model.** A self-hosted instance for one team. The attackers considered are: anyone who can reach the port, a
foreign web page that tries to act through a signed-in browser (CSRF), a DNS-rebinding page, an oversized or malformed
request, and a leak of secrets through logs. Not considered: a malicious user who holds the token (there is one shared
token, no roles), or a compromised host.

### Access protection

- One API token (`OPENARTIFACT_API_TOKEN`, at least 32 characters) protects the whole application: pages, the browser API,
  Swagger, `/api/v1` and `/mcp`. Open paths: `/health`, `/login`, `/logout`, `/static/`. Without a token the pages and the
  browser API are open (the startup log warns), and `/api/v1` and `/mcp` answer `401`.
- A request is accepted with `Authorization: Bearer <token>` (compared in constant time) or with a valid session cookie.
  The MCP server accepts only the bearer header.
- **Session cookie:** `<issued-at>.<HMAC-SHA256(secret_key, "session:<issued-at>:<token>")>`, never the token; the server
  refuses it after 30 days; `HttpOnly`, `SameSite=Strict`, `Path=/`; when secure also `Secure` and the name
  `__Host-oa_session`. Secure follows `OPENARTIFACT_COOKIE_SECURE` (`auto`: the request scheme is https). Changing the token
  or the secret key ends all sessions; there is no per-session revocation, and logout only clears the browser's cookie.
- The application **refuses to start** with a token shorter than 32 characters or with a token and a missing or default
  secret key. A wrong sign-in costs half a second; there is no rate limiting beyond that.

### Request hardening (middlewares, outermost first)

| Layer | Rule |
|-------|------|
| Security headers | CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'` (`'unsafe-inline'` for scripts only with `OPENARTIFACT_CSP_SCRIPT_UNSAFE_INLINE`); `X-Content-Type-Options: nosniff`; `Referrer-Policy: same-origin`; `X-Frame-Options: DENY`; `Strict-Transport-Security` over HTTPS. `/api/docs` has its own policy that allows `cdn.jsdelivr.net` |
| Host check | `OPENARTIFACT_ALLOWED_HOSTS` (supports `*.example.com`); other hosts get `400`; empty list: no check; `/health` exempt. Covers `/mcp` too |
| Body limit | 1 MiB (`OPENARTIFACT_MAX_REQUEST_BYTES`, `413`); 4096 bytes for `/login` |
| Cross-site guard | Unsafe methods get `403` when `Sec-Fetch-Site` is `cross-site` or `same-site`, or `Origin` differs from `Host`; requests without those headers (curl, scripts, MCP clients) pass; unsafe `/api` requests with a body must be `application/json` (`415`) |
| Caps | `OPENARTIFACT_MAX_CONCURRENT_RUNS` (`429`), `OPENARTIFACT_MAX_SSE_SUBSCRIBERS` (`503`) |

A reverse proxy must keep the `Host` header and send `X-Forwarded-Proto` (see the
[reverse proxy guide](../../../guides/reverse-proxy.md)).

### Secrets and logging

- Secrets are only environment variables: none in code or database. The logging filter masks the configured token and
  secret key and values after secret-looking names (chapter 8.3). `deploy/.env` is git-ignored and excluded from the
  image by the `.dockerignore` allow-list.

### Container

- Multi-stage build; the runtime image has no build tools or development dependencies, and the build context is an
  allow-list (`.dockerignore`).
- Runs as UID 1000 on a **read-only root file system**; only `/data` (volume) and a tmpfs `/tmp` are writable; `/app` and the
  installed package are root-owned. All capabilities dropped, `no-new-privileges`, 256 processes, 512 MB. No privileged
  mode, no Docker-in-Docker.
- Published on `127.0.0.1` by default; `OPENARTIFACT_BIND=0.0.0.0` opens it to the network and needs a token.
- CI audits the runtime dependencies weekly (`pip-audit`) and Dependabot proposes updates.
