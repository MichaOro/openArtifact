## 8.3 Logging & Observability

- **One handler** on the `openartifact` logger (module loggers are `openartifact.<module>`) writes to stdout in one plain
  format: `%(asctime)s [%(levelname)-8s] %(name)s: %(message)s`. There is no JSON format and no production/development
  difference. The logger does not propagate to the root logger, so the MCP SDK's own root logging does not duplicate or
  reformat messages. `create_app()` configures logging after building the MCP server.
- **Level** from `OPENARTIFACT_LOG_LEVEL` (default `INFO`); the `mcp` and `httpx` loggers log warnings only unless the level
  is `DEBUG`. uvicorn runs with the same level and keeps its access log on; it also logs the traceback of an unexpected
  error.
- **Secret masking.** A filter masks secrets in the finished message, in the formatted arguments and in tracebacks: the
  configured API token and secret key (when at least 8 characters) wherever they appear, and any value after a
  secret-looking name (`secret_key`, `password`, `token`, `api_key`, `apikey`, `authorization`, `credential`,
  `database_url`) written as `name=value`, `name: value` or `'name': 'value'`.
- **What is logged:** start and shutdown, version, environment and level, warnings for a default secret key and for a missing
  token, the database path after a `SELECT 1`, run recovery, application errors, one ERROR line per unexpected exception.
  The database connection is checked with `SELECT 1` at startup; the application does not check that WAL mode is on.
- **Health:** `GET /health` (status, application, version), used by the compose health check.
- Container logs: `docker compose -f deploy/docker-compose.yml logs -f`. There are no metrics or traces yet.
