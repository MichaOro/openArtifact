## 8.7 History and Retention

Decisions: [ADR-025](../../adr/025-execution-history-and-retention.md) (history), [ADR-026](../../adr/026-origin-of-a-run-started-by.md)
(origin), [ADR-027](../../adr/027-execution-flow-by-replay-over-the-frozen-snapshot.md) (flow),
[ADR-028](../../adr/028-global-executions-page-and-keyset-paging.md) (global list). Runtime: [6.9](../06-runtime-view/06.09-history-retention-and-flow.md).
User-facing text: [execution history guide](../../../guides/execution-history.md).

**Run and execution.** The *run* (`pipeline_runs`) is the current state of an artifact: one row per artifact, reused by
every start. An *execution* (`executions`) is one start: it has a number per artifact (counter `tasks.execution_seq`,
unique per artifact, never reused), its origin (`started_by`: `user`, `api`, `mcp`; `system` is reserved), copies of the
pipeline, stage and action names (so history stays readable after renames and deletions), a copy of the frozen
snapshot, its status (the run statuses), a note, the final stage and action, a step count and timestamps. The *steps*
(`run_node_results`) belong to the execution. Migration 0023 turned each existing run into execution number 1.

**What is stored.** Steps hold the outcome, port, exit code, reason, data and the **output**, already masked
([8.6](08.06-credential-store.md)). One output is at most 256 Ki characters; all outputs of an execution together at most
1 Mi characters (the oldest are replaced by a marker). The snapshot holds the definitions as they were at the start, so
an execution can be drawn later even if the pipeline changed. It also means each execution carries a full copy.

**Retention.**

| Rule | Value |
|------|-------|
| Operator's guard | `OPENARTIFACT_EXECUTION_HISTORY_DEFAULT_KEEP` as the most executions per artifact (default 50; `0` keeps everything); no per-artifact policy (ADR-057) |
| Rules | the global retention rules of ADR-052 (*Executions → Retention*) |
| Never deleted by retention | the newest execution of the artifact; a running execution (it counts toward the number kept) |
| When it runs | at every start and every end of an execution of the artifact; the rules also when they are saved |
| Manual | delete one finished execution, or clear all finished ones; a running one answers `409` |

**Growth.** Retention bounds the number of rows per artifact, not the size of the database: with the default 50, one
artifact can hold 50 snapshots and up to 1 Mi characters of output each. The database runs with `auto_vacuum = FULL`
(ADR-005, update of 2026-11-22), so deleted rows give their pages back to the file system and the file shrinks. `0` as the guard keeps all executions of every artifact
(the rules then do the work). Sizing and the cost of a large history are in chapter 11.

**Events.** `execution.updated` (`{task_id, execution}`) when an execution starts and whenever its status changes;
`execution.deleted` (`{task_id, id}`) for each deletion by hand, by retention or by the rules. They are published
after the commit, like all events ([8.4](08.04-board-concepts.md): the server is the authority, the client's `upsert` is
idempotent). The bus is in-process and not replayed; a client that reconnects reloads.

**Reading.** Per artifact (`/api/tasks/{id}/executions`, `/api/v1/artifacts/{ref}/executions`, MCP `list_executions`),
global (`GET /api/executions`, MCP `list_all_executions`) with filters and keyset paging, and the flow (`.../flow`).
Pages: the History tab of the artifact dialog, `/executions`, `/artifacts/{ref}/executions/{id}` and `/?artifact=N` as a
deep link from the list to the board.
