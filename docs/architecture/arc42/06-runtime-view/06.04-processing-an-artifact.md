## 6.4 Processing an artifact

```
User: "Start processing" (pipeline, stage, action)       Script: POST /api/v1/artifacts/{ref}/run    started_by = api
  started_by = user                                      Agent:  MCP tool start_processing           started_by = mcp
  → POST /api/tasks/{id}/run                             (the same engine call; "system" exists but nothing sets it yet)
      refuse: 404 unknown artifact, 409 already running or being started, 422 stage/action not in the pipeline,
              429 run cap reached (details in 6.6: in-process claim, conditional UPDATE, INSERT ... ON CONFLICT DO NOTHING)
      one transaction: snapshot of the pipeline and its action definitions, the run row, one run_stages row per
        stage, one execution row (number, started_by, snapshot copy), retention applied
      publish run.updated, execution.updated (and task.updated when pipeline, stage or action changed)
        → every browser: card shows "<stage> · running", the dialog locks, the History tab and /executions get the new row
  → background task, per artifact:
      for each stage from the start:  stage running → action → (its definition: trigger → timer / Code / HTTP → output)
          On Pass / On Error → next action, or the end of the stage → stage passed
        each node of a definition: execute (a Code or HTTP node resolves its secrets and is masked, 6.7 / 6.8),
        store one run_node_results row, publish run.updated; each save of the run publishes it too
      after the last stage: done        (a missing connection or 1000 steps: failed, with a note)
      every end (done, failed, stopped): close the execution, apply retention, publish execution.updated / deleted
User: "Stop processing" → POST /api/tasks/{id}/run/stop: the task is cancelled (a running Code process group is killed),
  status stopped, stage and action kept; the lane, parent and order are editable again; start again from there.
Container restart: orphan code processes are ended, runs and executions that were running become stopped ("interrupted").
```

`started_by` records how a run was started: `user` (the browser, the default of `ArtifactService.start`), `api`
(`/api/v1`) or `mcp` (the MCP server). `system` is a valid value for starts by the application itself; nothing starts
a run that way today. Runs from before migration 0024 keep the value `system` they were stored with.

While the run is `running`, `PATCH /api/tasks/{id}` with `status`, `before_id` or `parent_id`, and
`DELETE` answer 409 (ADR-013). Deleting a running execution answers 409 as well ("stop it first").
