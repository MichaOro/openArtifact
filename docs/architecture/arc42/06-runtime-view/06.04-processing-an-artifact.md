# 6.4 Processing an artifact

```
User: "Start processing" (pipeline, stage, action)         System: the same call, started_by = system
  → POST /api/tasks/{id}/run
      refuse: 404 unknown artifact, 409 already running or being started, 422 stage/action not in the pipeline,
              429 run cap reached (claim in process, conditional UPDATE, INSERT ... ON CONFLICT DO NOTHING)
      snapshot of the pipeline and its action definitions, one run row, one run_stages row per stage
        (stages before the start: passed or skipped; from there on: pending)
      publish run.updated (and task.updated when pipeline, stage or action changed) → every browser: card shows "<stage> · running", the dialog locks
  → background task, per artifact:
      for each stage from the start:  stage running → action → (its definition: timer, ... → output)
          On Pass / On Error → next action, or the end of the stage → stage passed
        each step: save, publish run.updated
      after the last stage: done        (a missing connection or 1000 steps: failed, with a note)
User: "Stop processing" → POST /api/tasks/{id}/run/stop: the task is cancelled, status stopped,
  stage and action kept; the lane, parent and order are editable again; start again from there.
Container restart: runs that were running become stopped ("interrupted").
```

While the run is `running`, `PATCH /api/tasks/{id}` with `status`, `before_id` or `parent_id`, and
`DELETE` answer 409 (ADR-013).
