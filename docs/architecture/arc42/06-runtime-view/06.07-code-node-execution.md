## 6.7 Executing an Execute Command node

An Execute Command node runs a shell or Python script as a child process of the application. It is the only place where the
application runs code it did not ship; what protects against what, and what does not, is in
[8.5](../08-cross-cutting-concepts/08.05-execution-nodes-safety.md).

```
engine._run_action → EXECUTORS[CODE].run (executors._code)
   settings.code_nodes_enabled false                → fail "Execute Command nodes are disabled"
   open mode without OPENARTIFACT_CODE_NODES_WITHOUT_TOKEN → fail ("Execute Command nodes need OPENARTIFACT_API_TOKEN ...")
   names of the secrets the node asked for (parse_name_lines) → _with_secrets (6.8)
      run_code(language, code, timeout, output limit, env = secret values, limits, node_id)
         1  empty code → fail
         2  mkdtemp /tmp/oa-code-XXXX (mode 0700), write script.sh or script.py
         3  new marker (random 32 hex); count the user's current tasks (/proc) as the NPROC baseline
         4  argv = python -I -c <wrapper> <json spec> <sh|python -I script>
              start_new_session=True (own process group), stdin /dev/null, stdout and stderr pipes,
              environment = secrets + PATH, LANG, HOME=<temp dir>, OPENARTIFACT_CODE_RUN=<marker>
         5  code_registry.record: <tmp>/openartifact-code-<uid>/<pid>-<marker>.json
         6  the wrapper (before exec): checks that its parent is still the application,
              setrlimit CPU, AS, NPROC, FSIZE, NOFILE, CORE (a limit that cannot be set → exit 125, node fails),
              restores SIGPIPE/SIGXFSZ defaults, prctl(PR_SET_PDEATHSIG, SIGKILL), execvp the real command
         7  two readers collect stdout and stderr: the first limit bytes (code_output_limit_bytes) and the last 8 KiB of stdout
         8  wait for the process, at most timeout_seconds (1 to 600)
              timeout → SIGTERM to the group, 2 s grace, then SIGKILL; reason "Timeout after N s"
         9  after the process ended: SIGKILL to the whole group (whatever it left in the background),
              drain the pipes for 1 s
        10  result: exit code 0 → pass, otherwise fail with a reason (signal, limit, exit code);
              the last non-empty stdout line may be {"ok": bool, "reason": str, "data": {...}} (the result protocol)
        finally (also when the run is stopped = the task is cancelled):
              forget the registry file, SIGKILL the group, reap the process, remove the temp directory
   masking of output, reason and data by the secret values (6.8)
engine._record → one run_node_results row; the port by outcome (On Pass / On Fail); run.updated published
```

Notes that matter when reading the code:

- The environment is built from scratch: no application setting (token, secret key) is passed on. The marker variable
  carries nothing sensitive; it lets the next start recognise descendants that changed their process group.
- The limits are per process (CPU, address space, file size, open files) or per user (`RLIMIT_NPROC`: the kernel counts
  all processes of the user, so the limit is the current count plus `OPENARTIFACT_CODE_PROCESS_LIMIT`). There is no cgroup.
- The limits are applied by a wrapper that then replaces itself by the real command (`exec`), so the application does
  not use `preexec_fn` in a threaded process. Where the `resource` module is missing the code runs unlimited and the
  result's reason says so.
- Hard kill of the application: `PR_SET_PDEATHSIG` kills the direct child, the registry lets the next start
  (`engine.recover`, [6.1](06.01-container-startup.md)) find and kill what was left in the background by pid and start
  time or by marker. Entries of an application that is still running are left alone. It needs `/proc`.
- A graceful shutdown cancels the run tasks; the `finally` above ends the processes.
- The application hardens itself against reading its own environment (`prctl(PR_SET_DUMPABLE, 0)`, applied before the
  first child), so a code process cannot read the token and the secret key from `/proc/<ppid>/environ`. This is a
  hardening step, not a sandbox.
