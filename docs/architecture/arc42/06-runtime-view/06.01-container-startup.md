## 6.1 Container startup

```
docker compose up        entrypoint                       application
────────────────────     ───────────────────────────      ──────────────────────────────────────
container starts    ──►  alembic upgrade head        ──►  exec openartifact  (cli.main → uvicorn)
                         (to head; failure: exit 1)        create_app: settings, security checks,
                                                           middlewares, MCP server, logging
                                                           lifespan: log, warn (default key, no token),
                                                           open engine + SELECT 1, engine.recover(),
                                                           MCP lifespan → serving on OPENARTIFACT_PORT
```

Steps:

1. `scripts/docker-entrypoint.sh` runs `alembic upgrade head`: creates the data directory if needed, applies all
   migrations up to head, and exits with status 1 when a migration fails (the container stops, `docker compose logs`
   says why). Then it runs `exec openartifact`, the same command as outside Docker. It sets no defaults of its own.
2. `openartifact.cli:main` reads the settings and starts uvicorn with the application factory
   (`openartifact.app:create_app`), the log level from `OPENARTIFACT_LOG_LEVEL` and `timeout_graceful_shutdown=3`.
3. `create_app` builds the application. It **refuses to start** (`ConfigurationError`) with an API token shorter than
   32 characters or with a token and a missing or default secret key. Logging is configured last, because
   building the MCP server makes the MCP SDK touch the root logger.
4. The lifespan logs the version and environment, warns about a default secret key and about a missing token, builds
   the shared database engine (WAL and foreign keys per connection), runs `SELECT 1`, and calls `engine.recover()`:
   runs that were `running` when the process ended are set to `stopped` with the note "interrupted" (skipped with a
   warning if the database is not migrated yet). The MCP server's own lifespan runs inside it.
5. The server listens on `OPENARTIFACT_HOST:OPENARTIFACT_PORT`. The compose health check calls `/health` through
   Python's `urllib` (the image has no `curl`) with a 30 s start period.

Shutdown on `SIGTERM` (`docker stop`, `compose down`): the lifespan calls `engine.shutdown()` (cancels the run
tasks), closes the event bus (open streams end), disposes the database engine and logs "Shutdown complete".
Uvicorn waits at most 3 s for open connections.
