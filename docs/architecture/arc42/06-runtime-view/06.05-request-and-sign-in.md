## 6.5 A request and signing in

```
any request ─► SecurityHeaders ─► HostCheck ─► BodyLimit ─► CrossSiteGuard ─► AccessGate ─► route
                (adds headers)    400 bad Host  413 too big  403/415 unsafe    token set?      │
                                  (not /health)               requests          open path, Bearer or
                                                                                valid cookie?  else 401
                                                                                (HTML GET: 303 /login?next=)
/mcp: the same chain, then TokenProtected (bearer only)
```

**Signing in (browser).** `GET /login` shows the form (a redirect to `/` when no token is configured). `POST /login`
reads at most 4096 bytes, compares the token in constant time, waits half a second on a wrong one, and on success sets
the cookie `oa_session` (`__Host-oa_session` when secure): `<issued-at>.<HMAC-SHA256 over the time and the token with the
secret key>`, `HttpOnly`, `SameSite=Strict`, `Path=/`, valid for 30 days on the server, then redirects to `next` (only a
path of the application). `POST /logout` forgets the cookie in the browser. Changing the token or the secret key ends all
sessions.

**A script or agent** sends `Authorization: Bearer <token>`; it has no cookie and no `Origin`, so the cross-site guard lets it
through. A browser request that gets a `401` (an expired session) is sent to `/login?next=<path>` by `http.js`.
