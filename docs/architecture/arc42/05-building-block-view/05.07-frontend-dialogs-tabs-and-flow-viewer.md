## 5.7 Frontend: dialogs, tabs and the flow viewer

Decisions: ADR-029 (dialogs), ADR-027 (flow), ADR-028 (global list). The file list is in [5.4](05.04-frontend-components.md).

### Dialogs

All dialogs share one structure. `Modal` wraps the native `<dialog>`; `ActionDialog` adds the request lifecycle (busy, no
double submit, close blocked while busy, error line); `ConfirmDialog` and `FormDialog` extend it, and `ArtifactDialog`
extends `FormDialog` with the only real specialisation: the view and edit modes of a saved artifact, the number, the lane
chip, the side rail and the tabs. A new dialog is `form_modal(id, title, fields)` in the template plus
`new FormDialog(new Modal(el)).open({title, values, submitLabel, onSubmit})`; inherit only when the dialog really differs.
`form_modal(..., reset="Reset to default")` adds an optional third button `[data-reset]` at the start of the footer; the lane rename dialog uses it (`tasks/lane-rename.js`). Wording is uniform: the submit button says "Create" (or "Save" when editing), the other button "Cancel". Field ids follow
`#<dialog id>-field-<name>`. `ConfirmDialog` is also used by the editor and the executions page for deletes.

A saved artifact's dialog is sized by its content, measured once when it opens (on the Details tab): height = min(content,
90 % of the window), but at least 560 px (the History tab needs room for its list); width = clamp(base width, 0.62 x
height, 800 px). The constants are CSS custom properties on `.modal__panel` (`--dialog-base-w` 34.75 rem,
`--dialog-ratio`, `--dialog-max-w`). View and edit keep that size; the body area scrolls. Create dialogs keep their small
fixed size; on a phone the dialog is full width.

### Tabs

`Tabs` (`components/tabs.js`) follows the ARIA tabs pattern: `role=tablist/tab/tabpanel`, `aria-selected`, roving
`tabindex`, Left/Right/Home/End, automatic activation. The markup carries the tabs
(`[role=tab][data-tab][aria-controls]`); the class only switches them. The saved artifact has **Details** and **History**.
The last tab used is kept while the page lives (not stored); edit mode hides the tabs. The History tab (`HistoryTab`) follows
the artifact the dialog shows and owns its list (`HistoryList`), detail (`HistoryDetail`) and retention editor
(`RetentionEditor`); live changes reach it through `handleEvent` from the page's one event stream (`execution.updated`,
`execution.deleted`), with a short debounced refetch.

### Flow viewer

The page `/artifacts/{ref}/executions/{id}` (`execution/flow-page.js`) is read-only. It loads the flow once without step
outputs, loads a step's output on demand, and while the execution runs reloads on its events. The state it shows is one
**visit** (a pass through one graph, entered from a node of its parent visit); it is kept in the URL (`?visit=N`), so reload,
a shared link and Back restore it. `visit-model.js` answers questions over the response without touching the DOM (which
visit, which node state: pass, fail, running, stopped, skipped, not-run; which passes exist below a node; the chain of
visits). `flow-view.js` draws the visit on the editor's `Canvas` and node views, read-only; states are never shown by colour alone (each has
a word and an icon; a node that did not run is dashed; a walked edge is thicker and numbered). `flow-panel.js` lists the
nodes the visit walked in order (the primary alternative to the canvas, focusable and readable by a screen reader) and
the details of the selected one; `breadcrumb.js` shows the chain from the pipeline down. Names, outputs and reasons are set with `textContent`, never as HTML.

### Global executions page

`executions/page.js` loads the first page for the filters in the URL (`status`, `started_by`, `pipeline`, `q`, `since`/`until`, or
a relative `range`), appends pages by cursor, and follows the event stream without moving rows: a row that is shown is
updated in place, an unseen execution only raises a "new executions" hint. The counters in `summary.js` toggle filters. A row
links to the flow page, to the artifact (`/?artifact=N`) and to the pipeline.
