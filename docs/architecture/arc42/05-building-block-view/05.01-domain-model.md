## 5.1 Domain Model

**Artifact** (code name `Task`) is the card on the Kanban board.

| Attribute | Meaning |
|-----------|---------|
| `id` | UUID, primary key |
| `number` | Human-readable number (`#12`); unique, assigned from a counter, never reused |
| `title`, `body` | Required title, optional free text (may reference other artifacts as `#12`) |
| `status` | Key of the artifact's lane (`lanes.key`; foreign key, `ON DELETE RESTRICT`, migration 0030); the first lane when none is given |
| `position` | Fractional sort key inside the lane |
| `parent_id` | Optional parent artifact (foreign key to `tasks.id`, `ON DELETE SET NULL`); a tree: one parent, any number of children, no cycles |
| `pipeline_id`, `stage_id`, `action_id` | The target the artifact starts with (migration 0019); choosing a pipeline selects its first stage and that stage's first action |
| `created_by` | Where it came from: `user`, `api`, `mcp` or `action` |
| `execution_seq` | The last execution number handed out for this artifact; numbers are never reused |
| `field_values` | The values of the artifact fields (JSON object text, default `{}`, only values that are set; at most 4 KiB); migration 0038, ADR-044 |
| `created_at`, `updated_at` | UTC timestamps |

**Artifact fields** (ADR-044, superseding the artifact types of ADR-035): `ArtifactField` (primary key `name`): `label`,
`kind` (`text`, `number`, `boolean`, `choice`), `default_json`, `options_json` (a choice's allowed values), `max_length`
(text), `min_value`, `max_value`, `integer_only` (number) and `position`. One list for all artifacts; the values live in
`tasks.field_values`, validated when an artifact is saved. Removing a field removes its values; a change that stored values
no longer fit is refused.

**Vocabulary** (ADR-015): a **pipeline** has **stages**, a stage has **actions**, and an action
is defined by an **action definition** whose **execution nodes** (trigger, timer, Code, HTTP, output) hold
the business logic. A **run** carries one artifact through a pipeline; each start of it is an **execution**.

**Graph** (ADR-012, ADR-015): pipelines and action definitions are both stored as a graph. `Graph`
(name, slug, status `draft`, `kind` `pipeline` or `action`), `GraphNode` (kind `trigger`, `stage`,
`action`, `pipeline`, `complete`, `timer`, `output`, `code` or `http`; position; size for stages; an action points
to its stage; `definition_id` links an action to an action definition and a `pipeline` node to the
pipeline it calls) and `GraphEdge` (output port of one node to an input port of another; one edge
per output). A stage has one `start` and one `end`, each serving both sides. Deleting a graph,
stage or node cascades through foreign keys. `GraphNode.seconds` and `fail_enabled` are columns; every other
setting of a node kind (Code: language, code, timeout, secrets; HTTP: method, URL, headers, body ...) lives in the JSON
column `config`, holding only the keys that were set (ADR-022).

**Run** (ADR-013, ADR-018): `PipelineRun` is the *current state* of an artifact (`task_id` unique, one row that every
start reuses): `pipeline_id`, `status` (`running`, `stopped`, `done`, `failed`), the current `stage_id` and `action_id`,
a `note`, `started_by`, a JSON snapshot of the pipelines and definitions it uses, `execution_id` (the current
execution) and one `RunStage` per stage (`pending`, `running`, `passed`, `failed`, `skipped`). `started_by` is `user`
(browser), `api`, `mcp` or `system`; nothing sets `system` yet (ADR-026). The counter table `task_number_seq` hands out
artifact numbers.

**TaskActivity** (ADR-058): one row per change of an artifact (`kind`: `created`, `lane`, `title`, `description`, `parent`, `field`, `pipeline`, `stage`, `action`) and one `run` trace per deleted execution, with the actor (`actor_kind`, `actor_name`), a small JSON `data` and `created_at`; at most 500 per artifact, deleted with it.

**Execution** (ADR-025): `Execution` is one row per start of an artifact, kept as history. It has a `number` per
artifact (from 1), copies of the pipeline name and of the starting and final stage and action names (no foreign
key: the history outlives the pipeline), `status` (the same set as a run), a `note`, `started_by`, `step_count`,
the frozen pipeline as `snapshot` (JSON, loaded on demand), `started_at` and `finished_at` (empty while it runs).
Its `context` column (migration 0028, ADR-033; JSON text, default `{}`, loaded on demand) is the run context: the
`card` (a copy of the artifact's parameters taken at the start, ADR-035), the
variables and the latest compact result of every node, written with every step; the run reads it through
`pipeline_runs.execution_id`, so there is one copy and it goes with the execution.
**`RunNodeResult`** is one step: every node of an action definition that the engine executed, in order (`seq`), with
`kind`, `outcome`, `port`, and for Code and HTTP nodes `exit_code`, `output`, `reason` and `data`. A step carries ids that
point into the snapshot (pipeline, depth, stage, action, definition, node) instead of foreign keys; only `run_id` and
`execution_id` are real ones, and a step is deleted with its execution.

**Secret** (ADR-024): `Secret` is a name (`^[A-Z][A-Z0-9_]{0,63}$`) and an encrypted value. Nodes refer to it by
name; the value is never returned by an API.

**Agent** (ADR-037, migration 0033): `Agent` (`name` unique ignoring case, `description`, `active`, `draft` as JSON text,
`published_number`, `version_seq`) and `AgentVersion` (`number` per agent from 1, never reused, the configuration as JSON,
`source_number` for a republished version, `published_via` `user` or `api`, `published_at`; rows are never changed;
`ON DELETE CASCADE` with the agent). An agent node refers to an agent by `config.agent_id`; the published version is
frozen into the execution's snapshot when it starts. `LlmProvider` (`kind` `openrouter` or `openai_compatible`, `name`,
`base_url`, `secret_name`, `allow_http`, `default_model`, `is_default`, the last connection test) has `LlmModel` rows
(`model_id`, `label`, `source` `fetched` or `manual`, `enabled`, `available`; `ON DELETE CASCADE`). A step's
`RunNodeResult.detail` (JSON, deferred) keeps what an agent sent and every attempt.

```
graphs ─┬─ graph_nodes (config JSON) ── graph_edges
        └─ kind: pipeline | action                         secrets
                                                       (name, encrypted value)
agents ── agent_versions                         llm_providers ── llm_models
(graph_nodes.config.agent_id → agents, checked by the service, no foreign key)
artifact_fields (one global list; values in tasks.field_values)
tasks ─┬─ pipeline_runs ── run_stages      current state, one row per artifact
       │        │
       │        └─ execution_id ──┐
       ├─ executions ◄────────────┘ ── run_node_results     history, one row per start,
       │       (task_id, number)         (execution_id, seq)   many steps per execution
       └─ parent_id → tasks              task_number_seq
```

`lanes` (migration 0030): `key` (primary key, at most 32 characters, generated from the title and never changed), `title` (1 to 40 characters,
unique ignoring case), `position` (order on the board), `style` (`normal` or `finished`, how the lane draws its cards; migration 0032, `CHECK`ed) and `created_at`. The three lanes `backlog`, `in_progress` and `done` are seeded; at most 12
lanes exist, a lane can be deleted only when no artifact references it, and the last lane stays. This replaces the `CHECK` constraint
on `tasks.status` (migration 0003) and the table `lane_titles` (0027). The downgrade moves artifacts of custom lanes to `backlog`.

The tables `projects` and `work_items` (migration 0002, with `repositories/`) never carried anything of the product
and are gone: migration 0026 drops them ([ADR-032](../../adr/032-removal-of-the-unused-workspace-model.md)). The models declare every index and
constraint of the migrations, and `alembic check` runs in the tests, so models and migrations cannot drift.
