## 5.2 Component Overview

Three entry points share one service and one run engine, inside a single `uvicorn` process:

```
Browser                          ┌─────────────────────────────────────────────────────┐
 pages, /api/*, SSE ───────────► │ middlewares: SecurityHeaders → HostCheck → BodyLimit │
Scripts ── /api/v1 (Bearer) ───► │              → CrossSiteGuard → AccessGate          │
LLM agents ── /mcp (Bearer) ───► ├─────────────────────────────────────────────────────┤
                                 │ api/tasks · runs · executions · graphs · secrets    │
                                 │ api/v1 · /mcp · api/events · web/routes (HTML)      │
                                 │            │                         │              │
                                 │            ▼                         ▼              │
                                 │  tasks/service.ArtifactService   secret_store       │
                                 │      │          │                (AES-256-GCM)      │
                                 │      │          └──► events.EventBus ──────────────┼─► SSE
                                 │      ▼                   ▲                          │
                                 │ tasks/repository   engine/RunEngine (asyncio tasks) │
                                 │ graph/repository     │ executors: code · http · timer
                                 │ engine/history(_query) │ flow (replay)              │
                                 │      └───────┬─────────┘          │ child processes │
                                 │  database.new_session (async SQLAlchemy) ──► SQLite │
                                 └─────────────────────────────────────────────────────┘
Container start: docker-entrypoint.sh → alembic upgrade head → exec openartifact (cli.main → uvicorn)
```

The browser API (`/api/tasks`, `/api/runs`, `/api/executions`), the integration API and the MCP tools are thin layers over
`ArtifactService`, which validates, applies the lock while an artifact is processed, publishes events, records
`created_by` and `started_by` and answers the history questions (executions, flow, steps, retention policy). The
pipeline editor's API (`/api/pipelines`, `/api/actions`) goes to `graph/repository`. The credential API
(`/api/secrets`, `/api/v1/secrets`) and the MCP tool `list_secrets` go to the `SecretStore`, which the executors also
use to resolve the secrets of a node at run time.

The `RunEngine` runs one `asyncio` task per active run. Every start opens an `Execution` in the transaction that
claims the run; for each node of an action definition the engine looks up the executor of its kind
(`engine/executors.py`), runs it, stores the result as a step and publishes `run.updated`; when the run ends, the
execution is closed and the retention policy is applied (`engine/history.py`, which publishes `execution.updated`
and `execution.deleted` after the commit). The path through the pipeline is not recorded: `engine/flow.py` replays
it from the frozen snapshot when the flow view asks. Details in [5.6](05.06-execution-engine-internals.md).
