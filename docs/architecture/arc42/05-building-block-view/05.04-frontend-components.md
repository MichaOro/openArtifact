## 5.4 Frontend components

Assets in `openartifact/static/`, templates in `openartifact/templates/`. No build step: ES modules are served as written, one
`<script type="module">` per page (no inline scripts, Content-Security-Policy `script-src 'self'`). Class prefixes:
`ge-` for the graph editor, `ef-` for the execution flow page. Every file is listed; paths are relative to `static/js/`
unless noted.

### Shared: styles, shell, HTTP

| Component | Location | Responsibility |
|-----------|----------|----------------|
| Design tokens | `css/tokens.css` | The only place with raw colours; light "Sand Dune", dark "Midnight Purple"; the button tokens (`--btn-*`) are the one definition of every control's states ([UI catalog](../../../guides/ui-catalog.md), ADR-059) |
| Styles | `css/base, components, forms, modal, task-dialog, editor, artifact-fields, agents, history, execution, executions.css` | Reset and the one scrollbar definition; shell, board, cards, the `action-row` and the sign-in form; form controls and the shared `is-danger` style; dialog; rail and lane chips (board page only); graph editor; the History tab; the flow page; the global executions page |
| Translations | `i18n.js` | `t`, `tn` (plural), `loadI18n`, the dictionary the page delivers as `<script type="application/json" id="i18n">`; the language switcher is in `main.js` (ADR-056) |
| Shell | `theme.js`, `main.js`, `nav-section.js`, `storage.js` | Theme and sidebar state, narrow-screen behaviour, the sidebar section; storage keys are defined once in `theme.js` (`window.OpenArtifact.keys`) and used through `storage.js` |
| HTTP | `http.js` | `fetch` wrapper; sends JSON, `ApiError` with `.detail`; a `401` sends the browser to `/login?next=...` |
| Reusable components | `components/` | `modal.js` (`Modal`), `action-dialog.js` (`ActionDialog`: busy state, error line, close guard), `confirm-dialog.js` (`ConfirmDialog`), `form-dialog.js` (`FormDialog`: fields from the markup, validation, `onSubmit(values)`), `tabs.js` (`Tabs`, ARIA tabs pattern), `alert-bar.js` (`AlertBar`), `popover.js`, `inline-name.js` (`InlineName`), `collapsible-nav.js` (`CollapsibleNav`), `lane-picker.js` (`LanePicker`: lanes, parents), `reference-picker.js` (`ReferencePicker`: `#` in the body), `icons.js` (clones icons from the page's `<template id="icons">`) |

### Artifact fields (`artifact-fields/`, `tasks/field-rail.js`; ADR-044)

| Part | Files | Notes |
|------|-------|-------|
| Editor | `artifact-fields/fields-editor.js` (`FieldsEditor`, an `ActionDialog`), opened from the board's menu next to *Add lane* | a row per field: label, name (derived from the label until edited), kind, default and what the kind needs; add, remove, reorder; says which values a removal drops; the server's `Field NAME:` messages appear at their rows |
| Rail | `tasks/field-rail.js` (`FieldRail`) | the *Fields* entry of the artifact dialog's rail: expands the rail, the fields hang indented below it (name, control); a change is saved at once, a refusal is shown under the field; locked while the artifact runs |
| Logic and client | `artifact-fields/model.js`, `api.js` | names from labels, the request body of a field, what a card shows (value or default), message parsing; `/api/artifact-fields` |

### Board and artifact dialog (`index.html`, `tasks/`)

| Component | Location | Responsibility |
|-----------|----------|----------------|
| Wiring | `tasks/main.js`, `tasks/api.js` | Actions with optimistic update and rollback; REST client; opens the artifact named by `/?artifact=N` once the board has loaded |
| Board | `tasks/board.js` | Single client state; idempotent `upsert`/`remove`; renders cards and relations |
| Lanes | `tasks/lanes.js`, `tasks/lane-rules.js`, `components/action-menu.js`, `Board.setLanes` | `LaneControls`: the "Add lane" `FormDialog` (its button is in the board's `action-row`), each lane's menu button (`ActionMenu`: Rename, Settings, Delete; Delete is `is-danger` and `aria-disabled` with a hint while the lane holds artifacts), the `LaneSettingsDialog` (`tasks/lane-settings.js`: switch and preview)  and the delete confirmation; the name is renamed in place by `InlineName` (`keepOpenOnError`: a refused name stays in the field with the message). `setLanes` shows the lanes from the API or the `board.lanes` event: new sections are clones of `<template id="lane-template">`, gone lanes disappear |
| Live sync | `tasks/events.js` | `EventSource`, resync on (re)connect; the alert bar says when the stream stopped for good; shared by the executions pages (`connectEvents`) |
| Drag and drop | `tasks/dnd.js` | Pointer-Events controller; reports a placement, knows no API |
| Artifact dialog | `tasks/artifact-dialog.js`, `tasks/references.js` | `ArtifactDialog` (create, view, edit; tabs Details and History; rail), `#n` rendering as links |
| Type and parameters | `tasks/parameter-form.js`, `tasks/parameters.js` | `ParameterForm`: the Type select, typed controls (text, number, switch, select) with required markers and defaults, the read-only parameter grid of the view (rows as tall as the controls, so the fitted size holds the form), inline server messages, the inline confirmation when a type change drops values; `parameters.js` is the pure logic (initial values, what a control means, `Parameter NAME:` messages, what a change drops) |
| Processing | `tasks/processing.js` | `ProcessingPanel`: Pipeline / Stage / Action fields and Start / Stop in the rail; state of every run kept current by `run.updated` |
| History tab | `tasks/history-tab.js` (orchestrator), `history-api.js`, `history-list.js`, `history-detail.js`, `history-row.js`, `history-step.js`, `history-format.js` | Executions of the shown artifact: list, one execution with its steps, delete and clear; follows `execution.updated` / `execution.deleted`; `history-row.js`, `history-step.js` and `history-format.js` are shared with the pages below |

### Templates (`templates/`)

`base_bare.html` (minimal layout), `base.html` and `login.html` extend it; page templates `index`, `graph_list`, `graph_editor`,
`executions`, `execution_flow`, `agents`, `agent_editor`, `providers`, `run_limits`; `components/*`: macros for sidebar, header, lane, modals (`alert()`, `form_modal()` /
`dialog_form()`, `confirm_modal()`), `create_task_modal.html` (the artifact dialog), `history_panel.html` and
`history_step_template.html` (the History tab and the step markup), `icons.html` (the only place with icon paths);
`components/nav.html` renders every navigation from `web/navigation.py`.

The dialog hierarchy, the tabs, the sizing rule and the flow viewer are described in
[5.7](05.07-frontend-dialogs-tabs-and-flow-viewer.md).
