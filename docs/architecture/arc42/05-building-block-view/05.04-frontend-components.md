## 5.4 Frontend components

Assets in `static/`, templates in `templates/`.

| Component | Location | Responsibility |
|-----------|----------|----------------|
| Design tokens | `css/tokens.css` | The only place with raw colours; light "Sand Dune", dark "Midnight Purple" |
| Styles | `css/base,components,forms,modal,task-dialog,editor.css` | Reset, shell/board/cards (and the sign-in form), form controls, dialog, rail and lane chips (`task-dialog.css`, only on the board page), graph editor (`editor.css`, prefix `ge-`) |
| Shell | `js/theme.js`, `js/main.js`, `js/nav-section.js`, `js/storage.js` | Theme and sidebar state, narrow-screen behaviour, the sidebar section; storage keys are defined once in `theme.js` (`window.OpenArtifact.keys`) and used through `storage.js` |
| HTTP | `js/http.js` | `fetch` wrapper; sends JSON, `ApiError` with `.detail`; a `401` sends the browser to `/login?next=...` |
| Board | `js/tasks/board.js` | Single client state; idempotent `upsert`/`remove`; renders cards and relations |
| Live sync | `js/tasks/events.js` | `EventSource`, resync on (re)connect; the alert bar says when the stream stopped for good |
| Drag & drop | `js/tasks/dnd.js` | Pointer-Events controller; reports a placement, knows no API |
| Dialogs | `js/tasks/artifact-dialog.js`, `references.js`, `delete-task-dialog.js`, `processing.js` | Dialog in create / view / edit mode, `#n` rendering as links, delete confirmation, start/stop processing |
| Wiring | `js/tasks/main.js`, `js/tasks/api.js` | Actions with optimistic update and rollback; REST client |
| Graph editor | `js/editor/` | `list.js` (pipeline / action list), `editor.js` (orchestrator), `graph-model.js`, `canvas.js`, `geometry.js`, `navigation.js`, `add-menu.js` (the "+" disclosure list), `inspector-panel.js`, `api.js`, `editor-main.js` |
| Node kinds and inspector | `js/editor/node-types.js`, `inspector.js` | `NodeView` and one view per kind (looks, ports, rule mirror); the inspector blocks (title, settings, connection, the New · Edit · Delete row) (ADR-014) |
| Reusable | `js/components/` | `Modal`, `ActionDialog` (busy state, error line, close guard; base of `ConfirmDialog` and `FormDialog`), `FormDialog` (fields from the markup, validation, `onSubmit(values)` decides where the result goes; base of `ArtifactDialog`), `AlertBar`, `Popover`, `InlineName`, `CollapsibleNav`, `LanePicker` (lanes, parents), `ReferencePicker` (`#` in the body), `icons.js` (clones icons from the page's `<template id="icons">`) |
| Templates | `templates/` | `base_bare.html` (minimal layout), `base.html` and `login.html` extend it; `index`, `graph_list`, `graph_editor`; `components/*`: macros for sidebar, header, lane, modals (`alert()`, `form_modal()` / `dialog_form()`, `confirm_modal()`), `icons.html` (the only place with icon paths); `components/nav.html` renders every navigation from `web/navigation.py` |

There are no inline scripts in the templates (Content-Security-Policy `script-src 'self'`). Class prefixes: `ge-` for the
graph editor.

### Dialogs

All dialogs share one structure. `Modal` wraps the native `<dialog>`; `ActionDialog` adds the request lifecycle (busy, no double submit, close blocked while busy, error line); `ConfirmDialog` and `FormDialog` extend it, and `ArtifactDialog` extends `FormDialog` with the only real specialisation: the view and edit modes of a saved artifact, the number, the lane chip and the side rail. A new dialog is `form_modal(id, title, fields)` in the template plus `new FormDialog(new Modal(el)).open({title, values, submitLabel, onSubmit})`; inherit only when the dialog really differs. Wording is uniform: the submit button says "Create" (or "Save" when editing), the other button "Cancel". Field ids follow `#<dialog id>-field-<name>`.

A saved artifact's dialog is sized by its content, measured once when it opens: height = min(content, 90 % of the window), width = clamp(base width, 0.62 × height, 800 px). The constants are CSS custom properties on `.modal__panel` (`--dialog-base-w`, `--dialog-ratio`, `--dialog-max-w`). View and edit keep that size; the body area scrolls. Create dialogs keep their small fixed size; on a phone the dialog is full width.
