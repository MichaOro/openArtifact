## 5.4 Frontend components

Assets in `apps/backend/openartifact/static/`, templates in `templates/`. No build step: ES modules are served as written, one
`<script type="module">` per page (no inline scripts, Content-Security-Policy `script-src 'self'`). Class prefixes:
`ge-` for the graph editor, `ef-` for the execution flow page. Every file is listed; paths are relative to `static/js/`
unless noted.

### Shared: styles, shell, HTTP

| Component | Location | Responsibility |
|-----------|----------|----------------|
| Design tokens | `css/tokens.css` | The only place with raw colours; light "Sand Dune", dark "Midnight Purple" |
| Styles | `css/base, components, forms, modal, task-dialog, editor, artifact-types, agents, history, execution, executions.css` | Reset and the one scrollbar definition; shell, board, cards, the `action-row` and the sign-in form; form controls and the shared `is-danger` style; dialog; rail and lane chips (board page only); graph editor; the History tab; the flow page; the global executions page |
| Shell | `theme.js`, `main.js`, `nav-section.js`, `storage.js` | Theme and sidebar state, narrow-screen behaviour, the sidebar section; storage keys are defined once in `theme.js` (`window.OpenArtifact.keys`) and used through `storage.js` |
| HTTP | `http.js` | `fetch` wrapper; sends JSON, `ApiError` with `.detail`; a `401` sends the browser to `/login?next=...` |
| Reusable components | `components/` | `modal.js` (`Modal`), `action-dialog.js` (`ActionDialog`: busy state, error line, close guard), `confirm-dialog.js` (`ConfirmDialog`), `form-dialog.js` (`FormDialog`: fields from the markup, validation, `onSubmit(values)`), `tabs.js` (`Tabs`, ARIA tabs pattern), `alert-bar.js` (`AlertBar`), `popover.js`, `inline-name.js` (`InlineName`), `collapsible-nav.js` (`CollapsibleNav`), `lane-picker.js` (`LanePicker`: lanes, parents), `reference-picker.js` (`ReferencePicker`: `#` in the body), `icons.js` (clones icons from the page's `<template id="icons">`) |

### Artifact types page (`artifact_types.html`, `artifact-types/`)

| Part | Files | Notes |
|------|-------|-------|
| List | `artifact-types/page.js` | create / rename (`FormDialog`), delete (`ConfirmDialog`, disabled with the reason while artifacts use the type); reloads on `artifact_types.changed` and artifact events |
| Parameter editor | `artifact-types/fields-editor.js` (`FieldsEditor`, an `ActionDialog`) | a row per parameter: label, name (derived from the label until edited), kind, required, default and what the kind needs; add, remove, reorder; the server's `Field NAME:` messages appear at their rows |
| Logic and client | `artifact-types/model.js`, `api.js` | names from labels, the request body of a field, message parsing; `/api/artifact-types` |

### Agents and providers (`agents.html`, `agent_editor.html`, `providers.html`, `agents/`)

| Part | Files | Notes |
|------|-------|-------|
| Agent list | `agents/list-page.js` | create (`FormDialog`), delete (`ConfirmDialog`, disabled with the reason while nodes use the agent) |
| Agent page | `agents/editor-page.js` | the draft form (prompts, inputs, model and limits), save, publish, discard, versions with "Publish again", preview, the nodes that use it; never overwrites what is being typed when an event arrives |
| Providers page | `agents/providers-page.js` | provider cards with their models (switch, default, filter, add by hand), `ProviderDialog` (an `ActionDialog`: test, test and save; a typed key goes to the secret store) |
| Shared | `agents/api.js`, `agents/model.js` (pure: chips, overrides, mapping, facts of a step), `agents/view.js` (prompt blocks, inputs and attempts tables) | also used by the editor's inspector and the step of the history |
| Agent node inspector | `editor/agent-inspector.js` | the agent, one field per declared input, each setting as *From agent* or *Overridden* with Reset; asks the server's preview for what is in effect |

### Board and artifact dialog (`index.html`, `tasks/`)

| Component | Location | Responsibility |
|-----------|----------|----------------|
| Wiring | `tasks/main.js`, `tasks/api.js` | Actions with optimistic update and rollback; REST client; opens the artifact named by `/?artifact=N` once the board has loaded |
| Board | `tasks/board.js` | Single client state; idempotent `upsert`/`remove`; renders cards and relations |
| Lanes | `tasks/lanes.js`, `tasks/lane-rules.js`, `components/action-menu.js`, `Board.setLanes` | `LaneControls`: the "Add lane" `FormDialog` (its button is in the board's `action-row`), each lane's menu button (`ActionMenu`: Rename, Settings, Delete; Delete is `is-danger` and `aria-disabled` with a hint while the lane holds artifacts), the `LaneSettingsDialog` (`tasks/lane-settings.js`: switch and preview)  and the delete confirmation; the name is renamed in place by `InlineName` (`keepOpenOnError`: a refused name stays in the field with the message). `setLanes` shows the lanes from the API or the `board.lanes` event: new sections are clones of `<template id="lane-template">`, gone lanes disappear |
| Live sync | `tasks/events.js` | `EventSource`, resync on (re)connect; the alert bar says when the stream stopped for good; shared by the executions pages (`connectEvents`) |
| Drag and drop | `tasks/dnd.js` | Pointer-Events controller; reports a placement, knows no API |
| Artifact dialog | `tasks/artifact-dialog.js`, `tasks/references.js` | `ArtifactDialog` (create, view, edit; tabs Details and History; rail), `#n` rendering as links |
| Type and parameters | `tasks/parameter-form.js`, `tasks/parameters.js` | `ParameterForm`: the Type select, typed controls (text, number, switch, select) with required markers and defaults, the read-only parameter grid of the view (rows as tall as the controls, so the fitted size holds the form), inline server messages, the inline confirmation when a type change drops values; `parameters.js` is the pure logic (initial values, what a control means, `Parameter NAME:` messages, what a change drops) |
| Processing | `tasks/processing.js` | `ProcessingPanel`: Pipeline / Stage / Action fields and Start / Stop in the rail; state of every run kept current by `run.updated` |
| History tab | `tasks/history-tab.js` (orchestrator), `history-api.js`, `history-list.js`, `history-detail.js`, `history-row.js`, `history-step.js`, `history-format.js`, `retention-editor.js` | Executions of the shown artifact: list, one execution with its steps, retention editor, delete and clear; follows `execution.updated` / `execution.deleted`; `history-row.js`, `history-step.js` and `history-format.js` are shared with the pages below |

### Pipeline and action editor (`graph_list.html`, `graph_editor.html`, `editor/`)

| Component | Location | Responsibility |
|-----------|----------|----------------|
| List | `editor/list.js` | The pipeline / action list |
| Orchestrator | `editor/editor.js`, `editor/editor-main.js` | Connects model, canvas, inspector and dialogs; a refused change reloads the graph and shows the reason |
| Model and drawing | `editor/graph-model.js`, `canvas.js`, `geometry.js`, `navigation.js` | Client graph state and the calls that save it; the canvas (also used read-only by the flow page); geometry and routing of lines; the way back to the pipeline an action definition was opened from |
| Add menu | `editor/add-menu.js` | The "+" disclosure list |
| Node kinds | `editor/node-types.js` | `NodeView` and one view per kind (looks, ports, rule mirror), registered with `registerView`; loads `GET /api/node-types` |
| Inspector | `editor/inspector.js`, `inspector-panel.js`, `setting-controls.js`, `field.js`, `reference-completion.js` (pure: open `${` at the caret, candidates, filter, insert), `reference-suggest.js` (the popup, ADR-034) | Inspector blocks (title, settings, connection, the New, Edit, Delete row); one control class per setting type the server describes (integer, switch, text, lines, code, select); the shared labelled-field markup (ADR-014, ADR-022) |
| API | `editor/api.js` | REST client of the editor (also `listGraphs` for the processing panel) |

### Execution flow page (`execution_flow.html`, `execution/`)

| Component | Location | Responsibility |
|-----------|----------|----------------|
| Page | `execution/flow-page.js`, `flow-client.js` | Loads the flow (`GET .../flow`) and steps on demand, keeps it current by events, keeps the shown visit in the URL (`?visit=N`); reads only |
| Model | `execution/visit-model.js` | Pure logic over the flow response: visits, node states (pass, fail, running, stopped, skipped, not-run), passes, chain of visits |
| View | `execution/flow-view.js`, `flow-panel.js`, `breadcrumb.js` | The editor `Canvas`, read-only, with the walk drawn on it; side panel with the walked nodes as a list (the keyboard and screen-reader alternative to the canvas) and step details; breadcrumb |

### Global executions page (`executions.html`, `executions/`)

| Component | Location | Responsibility |
|-----------|----------|----------------|
| Page | `executions/page.js`, `api.js` | Loads pages with the keyset cursor, follows events without moving rows, delete through the artifact's endpoint |
| Filters | `executions/filters.js`, `filter-bar.js` | Filters as a value in the URL query string; the filter form |
| Summary and rows | `executions/summary.js`, `table.js` | Counters that act as filter toggles; rows built from a template |

### Templates (`templates/`)

`base_bare.html` (minimal layout), `base.html` and `login.html` extend it; page templates `index`, `graph_list`, `graph_editor`,
`executions`, `execution_flow`, `artifact_types`, `agents`, `agent_editor`, `providers`; `components/*`: macros for sidebar, header, lane, modals (`alert()`, `form_modal()` /
`dialog_form()`, `confirm_modal()`), `create_task_modal.html` (the artifact dialog), `history_panel.html` and
`history_step_template.html` (the History tab and the step markup), `icons.html` (the only place with icon paths);
`components/nav.html` renders every navigation from `web/navigation.py`.

The dialog hierarchy, the tabs, the sizing rule and the flow viewer are described in
[5.7](05.07-frontend-dialogs-tabs-and-flow-viewer.md).
