# Languages (i18n)

English is the source language of OpenArtifact; every other language is one file of translations. German is the first
one and ships complete: every text of the interface and of the node kinds has its German version. A language file may
leave keys out: what it does not translate shows in English, so a page is never empty or broken
([ADR-056](../architecture/adr/056-internationalisation.md)).

## Using it

Open the globe button in the header and choose a language. The choice is kept in a cookie (`oa_lang`, one year) and read by
the server, so the next page already arrives in that language. On the first visit, before anything is chosen, the browser's
`Accept-Language` decides; a language that does not exist falls back to English.

What is translated: everything the pages and scripts show (menus, buttons, dialogs, empty states, tooltips, `aria-label`s,
confirmations, the texts the interface writes itself) and, where a locale file has them, the texts of the node kinds
(labels, help, placeholders, option names, menu clusters, port labels, card captions).

What is **not** translated, on purpose:

- **Error messages of the API** (`{"detail": ...}`, the reasons a call is refused, MCP tool errors): they are part of the
  API contract and the same for every client. The interface shows them as it receives them.
- Log messages, OpenAPI descriptions, the documentation, texts you or an agent wrote (artifact titles, lane names,
  agent prompts, comments), the names of stored values (a node's `Get comments`, a status `done`).
- Messages of the single sign-in provider (`oidc.py`) and the text of an operator's SSO button.

## Adding a language

1. Copy `openartifact/i18n/locales/en.json` to `<code>.json` (`fr.json`, `it.json`; two or three letters, optionally
   `pt-br`). The file name is the language: it appears in the switcher at once.
2. Add `"_name": "Français"` (the language's own name) and translate the values. Keep the keys and the `{placeholders}`
   exactly (a placeholder may move in the sentence, not change its name). You may leave keys out: they show in English.
3. Plural keys come in forms: `key.one` and `key.other`; a language with more forms adds `zero`, `two`, `few`, `many`
   (the browser uses `Intl.PluralRules`; for the server add the rule to `plural_category` in `openartifact/i18n/__init__.py`).
4. Run `python3 tools/check_i18n.py --all`: it lists the keys that are still missing and fails on a changed placeholder.
5. Optionally translate node texts (below). Then restart; no build step.

### German glossary

`de.json` follows one vocabulary, so a word means the same on every page. Address the reader without "Sie": instructions
are in the imperative (`Wähle …`, `Gib … ein`), labels and buttons in the infinitive or as a noun.

| English | German | Note |
|---------|--------|------|
| Artifact | Artefakt | sub-artifact: Unterartefakt; "parent": Übergeordnetes |
| Lane | Spalte | |
| Stage | Stufe | |
| Action | Aktion | |
| Pipeline, Node, Token, Webhook, Secret, `MCP`, `API`, `HTTP` | stay English | product and protocol words (a "provider" of models is *Anbieter*) |
| Agent / Agents | Agent / Agenten | a node: *Agent-Node* |
| Execution | Ausführung | a run (the thing a started pipeline does): *Lauf*; one pass through a loop: *Durchlauf* |
| Credentials | Zugangsdaten | rotate: *erneuern*; revoke: *widerrufen* |
| Run limits | Laufgrenzen | |
| Retention | Aufbewahrung | |
| Tool (of an agent) | Werkzeug | |
| Draft / published | Entwurf / veröffentlicht | |
| On Pass, On Fail, On Error | Bei Pass, Bei Fail, Bei Fehler | the outputs of a node |
| fail, continue (option of "If the node fails") | fehlschlagen, fortfahren | the stored value stays `fail` / `continue` |

A long German word can break a narrow layout (`Einstellungen`, `Ausführungen`, `Zugangsdaten`, `Laufgrenzen`,
`Überschreibung`): buttons, tabs and node captions truncate with an ellipsis rather than wrap, so check a new text in
German as well as in English.

### Node kinds

The manifests (`graph/nodes/*.yaml`) stay the English source. A locale file overrides single texts by key; a key it does
not have leaves the manifest's text:

| Key | Overrides |
|-----|-----------|
| `nodes.<kind>.label` | the name of the kind |
| `nodes.<kind>.settings.<key>.label` / `.help` / `.placeholder` | a setting's texts |
| `nodes.<kind>.settings.<key>.options.<value>` | how an option of a select is shown (the stored value stays) |
| `nodes.<kind>.ports.<name>` | the label of a port |
| `nodes.<kind>.caption` | the caption template of the card (copy it and translate the fixed words around `{...}`) |
| `nodes.menu.<cluster>` | a cluster of the "+" menu (`Structure`, `AI`, `Agent tools`, `Apps and data`, `Core`, `Data`, `Flow`) |

`tests/test_i18n.py` fails when such a key names a kind, setting, option, port or cluster that does not exist.

## For developers

- **Templates:** `{{ t('page.board') }}`, with variables `{{ t('x.y', name=value) }}`, plural `{{ plural('count.step', n) }}`.
- **JavaScript:** `import { t, tn } from "../i18n.js"` (the path to `static/js/i18n.js`); `t("key", { name })`;
  `tn("count.step", n)` for a plural. The page delivers its dictionary as a data block
  (`<script type="application/json" id="i18n">`; a data block is not a script, so the strict CSP stays as it is). The
  dictionary is the language laid over English, so nothing flashes untranslated. Under Node (the unit tests) `i18n.js` reads
  `en.json`, so tests see the same English text and a missing key shows as the key.
- **Python:** `from openartifact import i18n; i18n.t("key", "de", name=...)` for text the server writes into a page.
- **Keys** are flat and dotted: `<area>.<what>`; shared words are in `common.`. Navigation entries are `nav.<key>.label` /
  `.tooltip` (built from the entry's key in `web/navigation.py`), page titles `page.<name>`.
- **The check:** `python3 tools/check_i18n.py` finds a key that is used but not defined, defined but not used, a language file
  with a key English does not have, and placeholders that differ from English. `tests/test_i18n.py` runs it, so drift fails the
  build. A key built at run time (`t('nav.' ~ item.key ~ '.label')`) counts its literal start (`nav.`).
- Do not split a sentence into pieces around markup if you can avoid it, and never build a sentence by joining translated
  words: give the translator the whole sentence with its `{placeholders}`.

Known limits: a few long help texts in templates are cut in pieces around `<code>` tags (each piece is one key); word order
inside such a sentence cannot change. Right-to-left languages need a layout pass that has not been done.
