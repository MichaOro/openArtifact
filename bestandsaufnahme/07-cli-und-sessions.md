## Überblick

The pipeline runs unattended AI agents as external CLI processes. Today the live path is: n8n (Coding workflow) claims a queue item, creates a git worktree per run, renders a versioned DB prompt into .aiforge/run/system.md + user.md, creates a Codeman 'shell' session (a tmux session on a dedicated tmux socket) in that worktree and types one composed command: `cd <worktree> && AIFORGE_*=... OPENCODE_CONFIG_CONTENT=... opencode-aiforge --model <provider/model> [--agent opencoder-pipeline] --prompt "$(cat user.md)"`. The launcher isolates config (own XDG dir, only a GitHub MCP, bot identity, secrets from vault-rendered env), starts OpenCode, keeps a per-run TMPDIR, reports sessionEnd exactly once even after SIGKILL, and can restart OpenCode in the same directory when a watchdog says so. A plugin inside OpenCode (aiforge-hooks.js) streams run events and tool calls to n8n (events, loop guard), pins the model on every message, aborts hung or rate-limited turns, and nudges once when a turn ends without a usable result. Model choice is a Run Profile -> cluster -> ordered endpoint list with health 'cooling', source blocks, one-run-per-model slots, a global cap and a recovery chain (retry same, next model, fallback cluster, Claude Sonnet, give up with human hand-off). All model traffic of the company models goes through LiteLLM (thin aliasing/retry/telemetry gateway; no budgets or fallbacks configured), with FreeLLMAPI behind a 'free-pool' alias. Usage is captured outside the terminal layer: an adapter tails opencode.db into telemetry.usage, LiteLLM/OpenRouter/Claude Code send OTel, and Grafana (AI Usage, AI Pipeline Control Center, Server load) reads Postgres. A Writing path (typed prompts into Codeman terminals, scraped ready-markers, Claude Code/Copilot/OpenCode launchers, resume by CLI family) still exists next to it. The owner's own 2026-11-15 handover (/home/orologas/codeman-cases/testcase/handover-eigenstaendiges-pipeline-tool.md) already frames the target: an AgentRunner interface (tmux+CLI or API), model clusters/fallback/quota/health as configuration, deterministic result validation, and a decision log for every automatic decision.

### Per-run isolated terminal session launch (Coding path)

- **Was sie tut:** For each pipeline step n8n creates a Codeman session (POST /sessions with workingDir=run worktree, mode 'shell', name 'Issue #N - title (action, Versuch k)'), starts the shell, waits for a ready marker and types one launch command with an exactly-once clientId/seq. The command sets env (AIFORGE_SESSION_ID=run id, AIFORGE_STALL_MS, AIFORGE_MAX_RUNTIME_MS, AIFORGE_EXPECT_FILES, AIFORGE_ACTION, AIFORGE_WATCH_AFTER_MIN/EVERY_MIN, optional AIFORGE_XDG_CONFIG_HOME, OPENCODE_CONFIG_CONTENT with instructions + per-agent temperature) and starts opencode-aiforge with --model, optional --agent and --prompt from a file. One OpenCode process per run; it dies with the session so memory is freed. Codeman created 3009 sessions, 2934 of them shell-mode pipeline sessions; stage names seen: wp-review, wp-implement, wp-review-gate, wp-apply(-gate), wp-build(-gate), wp-code-review(-gate), epic-gap-analysis/resolution, epic-finalise, epic-document, *-health.
- **Auslöser und Eingaben:** A claimed queue item with a resolved routing rule (agent_key, run_profile or model, temperature, stall_minutes, max_runtime_minutes, watch_after/every minutes), the issue payload, the worktree path.
- **Ergebnis und Zustand:** sessions row registered BEFORE launch so the first hook events resolve to it (launcher 'opencode-codeman', copilot_session_id = run id 'aif-<queue8>-<ts><rand>', codeman_session_id, workdir, action, attempt, model, cluster, run_started_at); Codeman session + tmux session codeman-<id8>.
- **Fehlerbehandlung:** Any start-step failure marks queue/issue/session failed with a comment and deletes the stray Codeman session; a prompt is only considered delivered when the plugin's userPromptSubmitted event arrives (waits up to 120 s, also accepts agentStop/stopFailure/errorOccurred as 'turn already ended').
- **Externe Systeme:** n8n, Codeman REST API, tmux, OpenCode binary, Postgres, GitHub MCP.
- **Abstraktion für das Produkt:** A 'Run' executor step: allocate an isolated, human-observable execution session, start an agent CLI from a declarative launch spec (workdir, env, model, agent, prompt files, limits), confirm it really started, and always tear it down at the end.
- **Beleg:** n8n GitHub.Agentic.Coding nodes 'Codeman: Create Run Session', 'Codeman: Launch Run', 'DB: Register OpenCode Session', 'DB: Wait Prompt Submitted', 'Codeman: Stop Stray Session'; /home/orologas/bin/opencode-aiforge; /home/orologas/.codeman/session-lifecycle.jsonl (counts of created/started modes and stage names); /home/orologas/docs/opencode-run-profiles.md.

### Launcher wrapper per CLI (config isolation, identity, secrets, model)

- **Was sie tut:** opencode-aiforge maps a model flag (--nemotron, --deepseek, --qwen or --model provider/model) to an OpenCode model, exports AIFORGE_MODEL, points XDG_CONFIG_HOME to ~/.config/aiforge-opencode/xdg (or the OAC variant, only if the path is below that tree), reads only vault-rendered env files for LITELLM/OPENROUTER/GOOGLE keys, sets the bot identity for gh/git/MCP, sets commit author to the owner (deploy rule of the hosting provider) while pushes/comments use the bot token via a git credential-helper override, and runs OpenCode WITHOUT exec so it can report the end. Companion wrappers do the same for other CLIs: copilot-squad (per-model prompt caps), claude-free, claude-qwen, claude-private, and the three per-project `*-opencode` scripts that attach the interactive TUI to the shared opencode server.
- **Auslöser und Eingaben:** First argument model selector, env AIFORGE_SESSION_ID / CODEMAN_SESSION_ID / AIFORGE_RESUME / AIFORGE_XDG_CONFIG_HOME, remaining args forwarded to OpenCode.
- **Ergebnis und Zustand:** Per-run TMPDIR (/tmp/aiforge-run.XXXXXX) removed at the end; marker file for sessionEnd claim; exit code of OpenCode returned.
- **Fehlerbehandlung:** Missing required key = hard exit 1 with a message (no fallback to environment or plaintext, by owner decision); invalid AIFORGE_XDG_CONFIG_HOME paths are ignored.
- **Externe Systeme:** OpenBao-rendered files under /run/openbao-secrets, OpenCode binary (~/.opencode/bin/opencode), git/gh.
- **Abstraktion für das Produkt:** CLI adapters as data: each runner type (opencode, claude, copilot, generic shell) declares how to build argv/env, which config root it may read, which identity it acts as, and which secrets it may receive; secrets are injected only into the child process environment.

### Run Profile -> cluster -> endpoint resolution

- **Was sie tut:** A card/issue carries a 'Run Profile' (single-select) that names a model CLUSTER, not a model. Writing path: Postgres pick_endpoint returns one best endpoint per cluster (own healthy+free > own healthy+busy (wait) > fallback-cluster healthy > cooling-fallback), n8n 'Code: Map Profile to Model Endpoint' picks the profile's row, defaults to 'Daily Driver', keeps stickiness to the running conversation's launcher if still healthy/free, applies a recovery override, and preflights the local Ollama PC (5 s). Coding path: a routing rule can force a run_profile or an explicit provider/model; 'Code: Resolve Model' takes the first enabled endpoint of the profile's cluster (own, then fallback cluster) whose provider is allowed (currently only 'ai-hub'), else rule.model, else the first enabled ai-hub endpoint of daily-driver; effective model and cluster are stored on the session.
- **Auslöser und Eingaben:** Run Profile field value, routing rule (run_profile/model), session stickiness, health state, launcher busy state.
- **Ergebnis und Zustand:** sessions.launcher/model/cluster; a start comment/run-log entry naming profile, model and rank in cluster ('picked_because': free, busy-wait, fallback-cluster, cooling-fallback).
- **Fehlerbehandlung:** Unknown/disabled profile: run closed with a comment and ai:failed; Ollama unreachable ends the run (no fallback cluster); a model is never switched inside a live process, only by restart.
- **Externe Systeme:** GitHub Project field (Run Profile), Postgres model_cluster/model_endpoint/model_health, n8n.
- **Abstraktion für das Produkt:** Named model tiers (profiles) resolved at run start to a concrete model by priority + health + availability, overridable per action/stage, with an allow-list of providers per use case and a recorded 'why this model' reason.
- **Beleg:** /home/orologas/repos/Netrats/.aiforge/run-profiles.md; /home/orologas/codeman-cases/testcase/docs/model-infrastruktur-bestandsaufnahme.md (sections 2-5, snapshot 2026-11-05); n8n GitHub.Agentic.Writing 'DB: Pick Cluster Endpoints', 'Code: Map Profile to Model Endpoint'; n8n GitHub.Agentic.Coding 'DB: Load Profile Endpoints', 'Code: Resolve Model', 'DB: Default Model'.

### Versioned prompt assembly and hand-off files

- **Was sie tut:** System and user prompts live as versioned DB rows with eight sections (identity, task, context, constraints, knowledge, examples, runtime, output), production preferred over experimental, highest version. n8n joins non-empty sections with blank lines and replaces placeholders ({{issue.url}}, {{issue.repo}}, {{issue.number}}, {{worktree}}, {{branch}}, work-package and epic values, gate/health target values). Retries append a 'Korrekturauftrag' (implementation: commits stay, fix exactly the reported points) or 'Wiederholung' paragraph; a human reply after a health pause is appended as 'Antwort des Users'; stage-specific paragraphs are added after the unresolved-placeholder check. Deterministic helper scripts pre-build narrow context files into .aiforge/run/ (manifest.md, epic-context.md, review-context.md + change.diff, epic.md/wps.json/manifest.json, pr-context.md). Prompts are written base64-encoded (never shell-interpolated); system.md is injected via OPENCODE_CONFIG_CONTENT instructions, user.md via --prompt (hard limit 120000 bytes); .aiforge/ is added to the repo's info/exclude. Live examples are only 2-3 KB each: the agent reads the repo and GitHub itself.
- **Auslöser und Eingaben:** agent_key of the routing rule, issue payload, work-package row, gate/health context, retry reason, user reply.
- **Ergebnis und Zustand:** Rendered system/user prompt files in the run worktree; unresolved-placeholder list; config ids and environments (production/experimental) recorded in the node output.
- **Fehlerbehandlung:** Missing active system/user config or unresolved issue URL stops the run with an error; oversize prompt stops the run; helper script failures never stop the run (|| true, status line only).
- **Externe Systeme:** Postgres prompt_evolution schema, SSH to the host, helper scripts.
- **Abstraktion für das Produkt:** Prompt templates as versioned, sectioned artifacts with typed placeholders, plus a 'context builder' stage that deterministically prepares small input files before the agent starts; retry/correction instructions are appended by the engine, not by the agent.

### Git worktree per run with branch modes and sweeper

- **Was sie tut:** Each run gets its own worktree under ~/worktrees/<repo>/issue-<nr>-<queue8> (or wp-<epic>-<WP> in parallel-WP mode): fetch origin, branch_mode 'epic-branch' reuses/creates epic/<N> (follows origin if ahead, keeps local unpushed commits, never tracks main), else a detached worktree from origin's default branch; node_modules is symlinked from the main clone and excluded. At run end the run's worktree is removed; aiforge-worktree-sweep (event-driven, no timer) removes only pipeline-pattern directories that are not active session workdirs, not claimed/processing queue ids, not touched within 30 min, plus the run's temp files and stale /tmp/aiforge-run.* dirs.
- **Auslöser und Eingaben:** Claimed queue item, routing rule branch_mode, epic number, WP id.
- **Ergebnis und Zustand:** Worktree directory, branch, 'AIFORGE wp-worktree {json}' status line in parallel-WP mode; sweep summary 'removed/kept/freed_mb'.
- **Fehlerbehandlung:** SSH node does not throw on non-zero exit, so a separate check node verifies the printed path; failure marks the run failed and hands over; sweep never fails (exit 0) and skips anything ambiguous.
- **Externe Systeme:** git, filesystem, Postgres (sessions, queue).
- **Abstraktion für das Produkt:** Workspace provisioning/cleanup service: one ephemeral workspace per run, derived from card/stage, with branch strategy as configuration and a deterministic garbage collector keyed on 'is any active run using this directory'.
- **Beleg:** n8n GitHub.Agentic.Coding 'OpenCode: Worktree Plan', 'SSH: Create Worktree', 'Code: Check Worktree'; n8n GitHub.Agentic.Events 'SSH: Remove Run Worktree', 'Code: Cleanup Command'; /home/orologas/bin/aiforge-worktree-sweep; /home/orologas/bin/aiforge-wp-worktree.

### Autonomous permission policy

- **Was sie tut:** Runs are unattended, so approval prompts are replaced by allow + explicit deny rules (last matching rule wins): bash allowed except sudo, rm -rf /, ~ or $HOME, force-push, mkfs, dd, `| sh`/`| bash`; external_directory allowed except /etc, /root, /boot, ~/.ssh, ~/.gnupg, ~/.aws, ~/.config, ~/.copilot, ~/.claude, shell profiles and .env files; 'question' denied (the agent asks the author through an issue comment instead); OpenCode's own doom_loop set to allow because the n8n ToolGuard is the loop authority. The OpenCode scheduler supervisor forces OPENCODE_PERMISSION {question:deny} for scheduled runs.
- **Auslöser und Eingaben:** Tool call + path/command pattern.
- **Ergebnis und Zustand:** Deny = error result to the model.
- **Fehlerbehandlung:** A denied action never hangs the run; the model works around it.
- **Externe Systeme:** OpenCode permission engine.
- **Abstraktion für das Produkt:** Declarative tool/path permission policy per runner profile, with denials returned to the model as errors instead of blocking prompts, and a human-question channel that is asynchronous (comment/inbox), never interactive.
- **Beleg:** /home/orologas/.config/aiforge-opencode/xdg/opencode/opencode.jsonc; /home/orologas/.config/aiforge-opencode/oac-xdg/opencode/agent/opencoder-pipeline.md; /home/orologas/.config/opencode/scheduler/supervisor.pl; /home/orologas/docs/opencode-run-profiles.md ('Autonomer Modus').

### Identity separation and secret injection

### Persistent terminal sessions on a dedicated tmux server (Codeman)

KillMode=process means restarting the web service does not kill tmux; on start Codeman recovers sessions ('recovered' events), detects dead panes ('mux_died'/'stale_cleaned'), and exposes live terminal to browsers. Observed now: socket 'default' has the owner's own claude session; socket 'codeman' has one claude-mode case session and one shell-mode pipeline session running opencode in a worktree. - **Fehlerbehandlung:** Stale registry entries cleaned at start; sessions of a killed server are re-adopted.
- **Externe Systeme:** tmux, node-pty, systemd user service.
- **Abstraktion für das Produkt:** A session host that keeps agent processes alive independently of the web server, lets humans watch/attach, survives restarts, and reaps dead sessions.

### Programmatic session control API

- **Was sie tut:** The pipeline drives Codeman only through REST: POST /sessions, POST /sessions/:id/shell, POST /sessions/:id/input {input, useMux, clientId, seq} (exactly-once delivery, input must end in \r to submit), GET /sessions/:id/wait-output (wait for a literal marker, from=buffer), GET /sessions/:id/terminal?tail= (read screen), GET/DELETE /sessions/:id. Ready detection is terminal scraping with whitespace stripped (OpenCode 'ctrl+p commands', Claude 'bypass permissions on', Copilot 'tab next tab', shell marker 'clear'); a Claude first-run trust dialog is answered with Down+Enter; typed prompts are sent as ONE line and Enter is sent separately after 2 s (Copilot swallows a \r sent with fast input; Claude Code and OpenCode submit on every newline); the Coding path replaced typed prompts with --prompt from a file plus the plugin's userPromptSubmitted confirmation. Names over 100 characters are rejected by Codeman (HTTP 400) and truncated to 96 + '...'. Codeman also offers wait-for-signal (stop/idle/exit; only claude/deepseek emit 'stop'), last-response from transcripts, inbox/ack messaging, SSE event stream and an MCP server.
- **Auslöser und Eingaben:** n8n code nodes, watchdog, humans.
- **Ergebnis und Zustand:** Session ids, terminal buffers, wait results (timeouts are HTTP 200 with timedOut:true).
- **Fehlerbehandlung:** Launch nodes throw when a marker is not seen within 60 x 1.5 s (Writing) or 60 s (shell ready); a Codeman wait timeout is not an error and must be looped.
- **Externe Systeme:** Codeman at 127.0.0.1:3001 (see unknowns), tmux.
- **Abstraktion für das Produkt:** Executor API contract: create session, send input idempotently, wait for a typed signal or marker, read output, delete; plus explicit 'ready' detection per CLI instead of assuming readiness.

### Exactly-once session end and stop disambiguation

### Session watchdog (digest, decision matrix, LLM judge, nudge/restart)

## Schmerzpunkte und Lehren

- `opencode --continue` resumes the most recent session of the WHOLE data directory, not of the working directory: with parallel runs a resumed run attached to another issue's session and received its prompts (Netrats#39/#50 landed in #40, 2026-11-02). Fix: always resolve the session by directory (opencode-aiforge last_session). Product: resume must be keyed by run lineage + workspace, never 'latest'. (/home/orologas/docs/opencode-run-profiles.md)
- The OpenCode TUI keeps the model of the resumed session and ignores --model, so a changed Run Profile silently ran the old model (Netrats#38, runs 210/211). Fix: pin the model on every user message via the plugin; the UI footer can still show the old model. Product: record the model per message/turn and enforce the selected model at the adapter.
- SIGTERM from the session host makes OpenCode emit session.idle before exiting, which looked like a normal finish and started gate checks and follow-up runs for a run somebody had just stopped (Netrats#38/#39). Signal handlers inside the plugin do not work (it is not in the main thread). Fix: 2.5 s grace before agentStop, sessionEnd from the launcher. Product: separate 'turn finished' from 'process ended', and make 'ended' an authoritative signal.
- A watcher that is a child of the launcher dies when the host kills the process tree, so no sessionEnd arrived and the issue stayed ai:processing forever (Netrats#40 ended by hand). Fix: setsid inside a subshell + marker-file claim so exactly one of two reporters sends. Product: run-end reporting must survive SIGKILL of the runner's whole group.
- OpenCode waits hours in a silent 'retry' state after a provider usage limit ('retrying in 7h') and a model request can hang with no error (seen with DeepSeek): nothing reaches the engine and the run hangs. Fix: plugin aborts on limit text or waits > 10 min, stall guard and runtime limit per action. Product: every stage needs liveness and time-box limits, and provider retry waits must not count as progress.
- Provider stream aborts depend on prompt size: AI Hub aborted ~10 % of DeepSeek requests at 25-75k prompt tokens and ~33 % at 75-125k (LiteLLM spend logs 30-31 Oct); a 70k cap cut aborts from ~100/day to near zero, but at 70k with ~48k fixed system/tool overhead Copilot compacted every ~10 calls (134 compactions in 15 sessions for Netrats#38 with no progress). On 2026-11-09 the author doubled Qwen to 140k (compaction at 70k broke gap analysis and slicing) and later DeepSeek too (backup opencode.jsonc.bak-20261111-deepseek140k). Docs and file comments still say 70k. Product: context window per model is measured configuration with a documented trade-off, not a constant. (/home/orologas/bin/copilot-squad header, opencode.jsonc comments)
- Long text written in one tool call is lost completely when the stream breaks mid-call (6 of 17 failed sessions in 24 h) and very long answers hit the output limit. Mitigation: write-in-sections rule (opt-in because Qwen rejected an additional system block). Product: prompt guidance + output-limit awareness belong to the adapter; partial writes should be recoverable.
- Qwen via the AI Hub accepts a single system message at the start: plugins adding system prompts, Claude Code's mid-conversation system messages and extra system blocks caused HTTP 400 'rejected as invalid by the model provider'. Shims: merge-system plugin, CLAUDE_CODE_MODEL_CAPABILITIES, drop_params. A Claude Code update can add new mid-conversation features that must be added to the switch list. Product: per-model capability flags and a smoke run after every plugin/CLI upgrade.
- Copilot CLI sends a non-disableable 'sentiment' call to model name gpt-5.4-nano; without an alias it fails. Lesson: CLIs call hidden auxiliary models; the gateway needs aliases for them and usage accounting must include them.
- OpenCode (Bun single binary) unpacks ~14 MB native libs into TMPDIR on every start and never removes them: 490 files / 3.7 GB in /tmp by 2026-11-09. Fix: per-run TMPDIR removed at exit (and by the detached watcher after SIGKILL). Product: give every run its own scratch dir and delete it.
- The shared `opencode serve` kept ~250 MB per finished session and burned more CPU over time (309 MB -> 3.3 GB after ~10 sessions, 136 % CPU on 2026-11-08). Mitigations: idle-only recycle with advisory lock + drain, then the architectural fix of one OpenCode process per run in its own session. Product: prefer process-per-run; if a long-lived server is unavoidable, include drain/recycle.
- opencode.db grew from 2.2 GB to 15 GB and filled the root disk (2.3 MB free on 2026-11-18); the emergency VACUUM INTO itself failed with 'database or disk is full'. Fixes: 12 h retention every 15 min, incremental auto_vacuum, snapshot/tool-output/log cleanup, DB compaction script. Product: agent-tool stores need retention from day one and an emergency path that does not need extra disk.
- (Inferred, evidenced) Retention is currently stalled: since ~2026-11-19 the log shows 'N Sessions noch nicht in telemetry.usage -> uebersprungen' growing from 3 to 399 and 'geloescht=0' on every 15-min run, permanent emergency mode (free 3.6 GB < 6 GB), DB back to 1.0 GB and rising. Likely cause: retention.py requires telemetry.usage rows with source='opencode', while the deployed adapter (dist/sync.js built 2026-11-18) skips every message whose provider is not 'opencode' (AI Hub/OpenRouter usage is booked via LiteLLM/OpenRouter), so sessions that used only those providers can never be deleted. Lesson: a deletion safety net must check 'usage captured anywhere', not 'captured by one specific ingestor'. (/home/orologas/.local/share/opencode/retention.py, retention.log; /home/orologas/repos/telemetry/opencode-adapter/src/sync.ts)
- A second, older cleanup (opencode-scheduler job: delete sessions older than 6 h, no telemetry check) exists with an enabled-but-inactive timer; the cleanup.sh script drops nearly all tables. Several competing cleanup mechanisms = confusion and data-loss risk. Product: exactly one retention owner.
- Prompts are visible in the process list (opencode --prompt ...), so `pkill -f <text>` from one agent killed another run's OpenCode (gate of #127 killed by the agent of #129). Fix: plugin blocks pkill/killall; agents may only kill PIDs they started. Related: secrets in argv leak to `ps` (an earlier Vercel-Blob token; at analysis time a postgres MCP helper started from an interactive Claude session shows its connection string with credentials in its command line - value not reproduced here). Product: never pass secrets or long prompts as argv; use env/files and process names that do not collide.
- Agents and services share one tmux server, so exported variables leak into agent sessions; the owner deliberately keeps tokens out of codeman-web/tmux env and uses a pipeline-mode agent that denies curl/sudo/.env access. Product: sandbox each run (container or user namespace) rather than relying on rules; Codeman sessions are not a security boundary.
- Agents wrote invalid JSON hand-over files (unescaped quotes) and only failed at the very end. Fix: validate .aiforge/*.json on write and return the parse error to the model immediately. Product: validate contract artifacts at write time.
- Turns ended without a usable result (empty answer, output limit, 'next I will...' without tool call, expected file missing). Fix: one automatic nudge. Product: bounded automatic follow-up before declaring failure.
- Loop guard false positive: running the same lint/test script after every atomic edit was blocked (Netrats#38). Fix: a file edit resets the counter for non-edit calls. Models also ignore denials, hence the abort escalation after the 3rd denial. Product: progress-aware loop detection.
- Comment pagination trap: the GitHub MCP returns 30 comments (oldest first); models read page 1 and reported 'no new comments' although decisions were on page 2 (Netrats#38). Fix: force page size 100 and append a 'fetch next page' hint; AGENTS.md also instructs reading all pages. Product: tool wrappers should rewrite arguments and annotate partial results.
- Terminal-driven control is fragile: ready detection by scraping buffer strings ('ctrl+p commands', 'bypass permissions on'; whitespace removed because the buffer drops spaces), first-run trust dialogs, Copilot swallowing \r with fast input, Claude/OpenCode submitting on every newline (prompt as one line, Enter after 2 s), shell-mode 'idle' firing only once, Codeman rejecting names > 100 chars. Fix in Coding path: prompt via file + --prompt and confirmation by a plugin event. Product: prefer structured launch/prompt channels (stdin/args/API) and event-based readiness over screen scraping.
- Model health logic gaps (owner's own audit 2026-11-05): only two error texts classify as blocks, 429/5xx/timeouts are indistinguishable; blocks are per SOURCE (a Zen free-limit blocks all Zen models in all clusters); no half-open probe; 'cooling-fallback' still starts a blocked model when everything is cooling; the recovery override is not re-checked; verify_score, data_policy and max_parallel are never read; errors are attributed via sessions.launcher so sessions sharing one copilot_session_id or ~20 simulated test errors skew counters; the trigger swallows exceptions; quota counters exist only for openrouter-free. Operating snapshot then: DeepSeek on AI Hub 31 of 51 sessions failed (30 recoveries) vs Qwen 0 of 37, though numbers are inflated by the join issue. Product: classify errors (rate limit, overload, outage, quota, content), keep history of blocks, make capability/quality fields effective or remove them.
- Free tiers are not stable or private: Zen free daily limits are unpublished and varied (~290 to 678 requests/day), Google free quota was exhausted by 4 requests/117k tokens in 25 s (RPM/TPM/RPD indistinguishable), Gemini free tier trains on data (data_policy 'trains') and the runs load the author's private knowledge files; free-pool prompts go to third parties. Product: data-policy metadata must gate which cards may use which models.
- Concurrency: two OpenCode sessions with the same model 'led to chaos', and the 4-core host is the real limit (max_active_runs 2). Product: per-model exclusivity and a global cap are required defaults; show queue reason (global-cap, model busy).
- Run lifecycle bookkeeping must happen BEFORE the effect: the session row is registered before launch (so first hook events resolve), the old session row is closed before its Codeman session is deleted (so the kill is not read as run end), the stale run's Codeman session is deleted before resuming the same conversation id (agent must release its session lock; +3 s sleep). Product: order operations so that events always find their run.
- Silent failure history: swallowed hand-over errors, trigger exceptions and plugin failures are all fail-open by design; the owner's rule is 'never swallow errors silently: decision log + visible comment'. Product: every automatic decision (recovery, nudge, restart, block) gets a logged reason.
- Cost data model complexity: five different code paths wrote shadow_cost (22,438 rows had shadow cost without entity/pricing link; a 72k-record repair was needed); actual_cost is mostly NULL; LiteLLM cost is 0 for company models; usage rows for OpenCode arrive without tokens first and are filled at completion (refresh window needed). Product: one canonical usage event with explicit provenance fields and one pricing resolver.
- Single-trigger ingestion broke when the architecture changed: the adapter initially relied on SSE from `opencode serve`; once runs became separate processes it needed inotify on the DB files. Product: capture usage from the durable store or gateway, not from a long-lived server's event stream.
- Configuration drift: docs say DeepSeek 70k while config says 140k; LiteLLM retries 2 (doc 11-05) vs 4 now; run-profiles doc and code disagree on pause semantics; many .bak files, plugin backups and dangling skill symlinks pointing into /tmp/opencode/litellm-skills; the Writing and Coding paths use different launch mechanics (typed prompts vs --prompt file). Product: one source of truth per setting, versioned, with change history.
- Owner-documented operational limits not yet tested end-to-end: loop-guard denial, compaction at length, recovery after stopFailure inside n8n, the merge-agent full run; the pipeline has no automated test suite (audit 2026-11-09 section 6). Product: simulate failures (kill, hang, quota, abort) in tests.
- The agent frameworks themselves are interactive by design: OAC agents require approval gates and ask permissions, which would stall unattended runs; the adapter script asserts each text replacement and refuses to build if upstream changed. Product: if third-party agent definitions are reused, an adaptation layer with fail-closed checks is needed.
